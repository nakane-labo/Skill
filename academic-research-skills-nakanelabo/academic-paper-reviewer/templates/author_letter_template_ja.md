# 作者向けレター（日本語版テンプレート）

編集決定書（Editorial Decision Package）は、後続の段階と機械的な照合のために書かれていて、内部の番号や機械行が多く、著者には読みにくい。審査が終わったあとに、決定書から著者向けの手紙を別に1通書く。そのためのテンプレート。

## いつ使うか

- `full` 審査で Phase 2（`editorial_synthesizer_agent`）の決定書とロードマップが完成したあと。
- 再審査（`re-review`）のあとにも、同じ見出しで書いてよい。
- 決定書の内容を言い換えて読みやすくするだけで、所見の追加・削除・順位づけはしない。

## 規則

1. 手紙の言語は、ユーザーの言語（既定は日本語）。見出しも訳す。原稿の引用は原稿の言語のまま。
2. 材料は、完成した決定書とロードマップ、Phase 0 の Coverage 節、Phase 1 の各査読レポート（良い点と質問のみ）。この手紙のために新しく査読しない。
3. 所見を足さない、落とさない、順位を入れ替えない。必須の修正と推奨の修正は、決定書のものを1件ずつすべて書く。
4. 機械行や内部の ID（`R1-W2` のような番号、`[CONSENSUS-3]` などのタグ）は書かない。査読者は「方法の査読者」「領域の査読者」のように役割で呼ぶ。
5. 原稿の文を引用するときは、原稿のとおりに写す。写せなければ、引用符を付けず言い換える。
6. 査読者が薦めた文献は、実在を確かめていなければ、確かめていない旨を書く（`shared/references/citation_existence_gate.md` で確かめてよい）。

## テンプレート

```markdown
# 審査結果のお知らせ

## 1. 決定と主な理由

決定: [採録 / 軽微な修正 / 大幅な修正 / 不採録]

[決定書の理由を、200〜300字で。主な理由を2〜3点]

## 2. 良い点

- [原稿の良い点を3〜5件。どの部分か（節・表・図）を添える]

## 3. 必ず直していただきたい点（必須の修正）

1. [内容] — 場所: [節・表・図・ページ] — [なぜ必要か、直す方向]
2. [...]

## 4. 直すことをお勧めする点（推奨の修正）

1. [内容] — 場所: [...] — [...]

## 5. 著者への質問

1. [審査者が確かめたい点]

## 6. この審査の範囲と限界

- 読んだ部分と読めなかった部分: [Coverage 節から。`not read` / `not readable` があれば、その部分と、読める版が必要なこと]
- 審査の進め方: [査読者の構成（役割）、決定の方法を2〜3行で]
- 薦めた文献の実在確認: [確認した / していない]
- 原稿の日付時点での文献の網羅を見ていること、および審査は助言であって最終判断は編集側にあること
```
