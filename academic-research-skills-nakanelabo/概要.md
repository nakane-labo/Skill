# academic-research-skills-nakanelabo — 日本語概要

このフォルダは、**研究調査・論文執筆・査読・全工程オーケストレーション**を段階的に進めるための **4 つのスキル**をまとめたパッケージです。Claude Code では**ルート `SKILL.md` のみ**がスキル定義。実務ではルートの振り分けに従い、該当サブフォルダの `SUBSKILL.md` と `agents/` を読んで進めます。

---

## 全体像

| サブフォルダ | スキル ID | 一言で |
|-------------|-----------|--------|
| `deep-research/` | `deep-research` | テーマの絞り込みから文献探索・統合・レポート化までの**学術調査** |
| `academic-paper/` | `academic-paper` | 体裁・引用形式を選び、**投稿可能な論文原稿**を段階的に執筆・整形 |
| `academic-paper-reviewer/` | `academic-paper-reviewer` | 国際誌を想定した**多視点ピアレビュー**（編集長＋査読者＋反論役） |
| `academic-pipeline/` | `academic-pipeline` | 上記3つを**ステージ管理**する軽量オーケストレーター（本処理は各スキルに委譲） |

**推奨の流れ（単体利用時）**: 上流が調査・下流が論文化なので、原則 **`deep-research` → `academic-paper`**。査読だけなら `academic-paper-reviewer`、研究から投稿まで一気に進めたい場合は `academic-pipeline`。

ルートの `SKILL.md` には振り分けと共通ルールの要約があります。各サブスキルの詳細は `deep-research/SUBSKILL.md` 等を読みます。

---

## 1. Deep Research（`deep-research/`）

- **目的**: 分野横断で扱える**厳密な学術調査**（研究課題の明確化、方法設計、体系的文献探索、ソース検証、統合、バイアス評価、必要に応じてメタアナリシス等）。
- **規模**: **13 エージェント**のパイプライン（研究問い、方法ブループリント、書誌、検証、統合、**社会学評論スタイルガイド準拠の参考文献運用（本バンドル既定）**・倫理・Devil's Advocate、システマティックレビュー用の RoB / メタアナ、任意の事後モニタリング等）。
- **主なモード例**: `socratic`（問いが曖昧なときの対話型ガイド）、`full`、`quick`、`lit-review`、`fact-check`、`systematic-review`（PRISMA 等）、既存論文の評価 `review` など。
- **主な成果物のイメージ**: RQ ブリーフ、方法論ブループリント、アノテーション付き書誌、統合レポート、INSIGHT コレクション等（詳細は各 `SUBSKILL.md` と `shared/handoff_schemas.md`）。
- **使わない場面**: 論文の「執筆のみ」→ `academic-paper`。構造化査読のみ → `academic-paper-reviewer`。全工程の段階管理 → `academic-pipeline`。

## 2. Academic Paper（`academic-paper/`）

- **目的**: **学術論文の下書きから引用整合・抄録・自己査読シミュレーション・形式変換**までを一気通貫で支援。
- **規模**: **12 エージェント**（インタビュー型の設定、文献戦略、構成、アーゲュメント、章ごとの下書き、引用コンプライアンス、二言語抄録、ピアレビュー模擬、LaTeX/DOCX/PDF/Markdown 整形、計画モード用ソクラテスメンター、図表コード生成、査読コメント解析のリビジョンコーチ等）。
- **対応例**: IMRaD、文献レビュー論、理論・ケース・政策ブリーフ・会議論文など。**引用形式**は intake で選択（本バンドルでは社会学系のとき **社会学評論スタイルガイド第3版** を正本にしやすい）。Chicago、MLA、IEEE、Vancouver 等も可。**抄録**は日本語＋英語の二言語対応。
- **品質関連（v2.5+）**: 任意の **Style Calibration**（過去論文から文体を学ぶ）、**Writing Quality Check**（機械的になりがちな表現の抑制。目的は品質向上であり、AI 隠蔽ではない）。**`literature_corpus[]`** があるときは `academic-pipeline/references/literature_corpus_consumers.md` の corpus-first フロー。
- **日本語の段落・流れ（v3.1.2・2026-05-17 追加）**: スライド資料「アカデミックライティングアドバイス v1」をテキスト化し、`academic-paper/references/academic_writing_advice_ja.md` としてバンドルに組み込み。原稿の主言語が日本語のとき、または段落・論旨の流れを重視するときは、下書き・自己レビュー・模擬査読で参照する。
  - **各段落**: トピック・センテンス → サポーティング・センテンス → コンクルーディング・センテンス（冗長なら省略）
  - **序論**: 広い話題 → 狭い話題（研究目的・介入まで）
  - **考察**: 狭い話題（結果）→ 広い話題（含意・展望）。限界・結論は末尾に置くことが多い
  - **段落間**: 各段落のトピック・センテンスだけ読んで大筋が通ること
  - **文間**: 後文が前文の後半を引き受ける（A→B→C→D の連鎖）
  - **文の形**: 主語と述語を近づける。一文一義（せめて二義）
  - **接続詞**: 必要最小限（「さらに」「ゆえに」等で流れを無理に作らない）
  - **連携ファイル**: `draft_writer_agent`・`peer_reviewer_agent`・`writing_quality_check.md`・`academic_writing_style.md` から相互参照。英語の register・hedging は従来どおり `academic_writing_style.md` が正本。
  - **元資料のコピー**: `~/Downloads/アカデミックライティングアドバイスv1.md`（正本パスへのリンク付き）
- **使わない場面**: 調査レポートだけ欲しい → `deep-research`。査読だけ → `academic-paper-reviewer`。

## 3. Academic Paper Reviewer（`academic-paper-reviewer/`）

- **目的**: 分野を自動推定し、**編集長（EIC）＋方法・領域・越境の3名の査読者＋ Devil's Advocate** の5視点から独立レビューを生成し、**編集決定レターとリビジョン・ロードマップ**にまとめる。
- **規模**: **7 エージェント**（分野分析とペルソナ設定、各レビュアー、編集合成）。
- **主なモード例**: 初回の本査読 `full`、改稿対応の検証 `re-review`、短時間の `quick`、方法に特化 `methodology-focus`、学習向け `guided`、査読キャリブレーション `calibration`（v1.9+）。Sprint Contract（Phase 1/2 ハードゲート）は `references/sprint_contract_protocol.md`。
- **使わない場面**: 論文を書きたいだけ → `academic-paper`。すでに査読コメントがあり改稿方針を立てたい → `academic-paper` のリビジョン／リビジョンコーチ。

---

## 4. Academic Pipeline（`academic-pipeline/`）

- **目的**: **研究 → 執筆 →（査読前）整合性検証 → 査読 → 改稿 → 再査読 → 再改稿 → 最終整合性検証 → 確定 → プロセス記録** までを、**ステージとチェックポイント**でつなぐ。
- **性質**: 中身の実作業は行わず、**段階検出・モード推奨・スキルの呼び分け・状態追跡**が中心。`deep-research` / `academic-paper` / `academic-paper-reviewer` および整合性検証エージェントを組み合わせる。
- **特徴の例**: ステージ完了ごとの**ユーザー確認**、査読前・最終の**学術的整合性（参照・データ等）の検証**、二段階査読、完了後の**プロセス記録**生成、任意の **`resume_from_passport`**、協働深度オブザーバー（`collaboration_depth_agent`）、コンプライアンス連携（詳細は `academic-pipeline/SUBSKILL.md`、`references/pipeline_state_machine.md`、`references/passport_as_reset_boundary.md`）。
- **使わない場面**: 文献調査だけ・査読だけなど**単機能**なら、該当スキルを直接使う方が適切。

## 使い分けの早見表

| やりたいこと | 使うスキル |
|-------------|------------|
| 研究テーマや問いを整理し、文献を体系的に調べたい | `deep-research`（曖昧なら `socratic`） |
| 論文を書き、引用・形式・抄録まで仕上げたい | `academic-paper`（構成から一緒に進めたいなら `plan`） |
| 日本語論文の段落構成・序論／考察の流れを整えたい | `academic-paper`（`academic_writing_advice_ja.md` を適用） |
| 投稿前に査読をシミュレーションしたい | `academic-paper-reviewer`（`full` 等） |
| 改稿が査読意図に沿っているか確認したい | `academic-paper-reviewer` の `re-review` |
| 調査から確定稿までを段階管理したい | `academic-pipeline` |

## 共通の考え方（中根ラボ運用）

- 主張には**根拠と引用**を必ず付ける。断定よりも、根拠の強さを示して説明する。
- データだけ、理念だけ、現場感覚だけに寄らず、**データ・制度・現場**を往復して判断する。
- 矛盾や不確実性は隠さず、エビデンスの質とあわせて**開示**する。
- 成果物には、各 `SKILL` が定めるとおり **AI 利用の開示**を入れる。
- ツールは手段。**「紙に向き合う時間を減らし、人と向き合う時間を増やす」** という目的を外さない。
